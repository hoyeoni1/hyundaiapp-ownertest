# 인수인계 문서 (handoff)

**작업한 사람(사람이든 AI 에이전트든)은 작업을 마칠 때마다 반드시 자기 인수인계 문서를 고친다.** 다음 사람이 이 문서만 읽고 바로 이어서 일할 수 있어야 한다.

## 규칙

1. **담당자별 파일 하나**: `docs/handoff/<영문-이름>.md` (예: `lee-sangjun.md`). 남의 파일은 고치지 않는다 → 각자 작업해도 충돌 없음.
2. **시작할 때**: 내 파일과, 내가 건드릴 영역 담당자의 파일을 먼저 읽는다.
3. **끝낼 때**(PR을 올리기 전, 또는 하루 작업을 멈출 때):
   - 맨 위 **"현재 상태"를 최신으로 덮어쓴다**(지난 내용은 지운다).
   - **"작업 기록"** 맨 위에 오늘 날짜 항목을 추가한다(지난 기록은 지우지 않는다).
4. **PR에는 인수인계 문서 수정이 함께 들어가야 한다.** 없으면 Claude 리뷰에서 돌려보내고 장호연은 머지하지 않는다(PR 템플릿 체크 항목).
5. 에이전트(Claude 등)에게 일을 맡겼으면, 에이전트에게도 같은 규칙으로 문서를 고치게 한다. 그 결과를 사람이 확인하고 PR에 넣는다.
6. 날짜는 `2026-10-30`처럼 절대 날짜로 쓴다("어제", "다음 주" 금지).

## 양식 (새 파일은 이걸 복사)

```markdown
# 인수인계 — <이름> (<역할>)

담당 경로: `app/.../domain/` 등

## 현재 상태 (YYYY-MM-DD 기준, 매번 덮어쓰기)

- 한 일 요약: 무엇이 동작하고, 무엇이 아직 안 되는지
- 진행 중 브랜치·PR: `feat/...` (PR 링크)
- 다음 할 일(우선순위 순):
  1. ...
- 막힌 점·질문(누구에게): ...
- 주의(함정·직접 겪은 이상한 동작): ...
- 확인 방법: 어떤 명령/콘솔 값/화면으로 동작을 확인하는지

## 작업 기록 (최신이 위, 지우지 않음)

### YYYY-MM-DD
- 한 일:
- 결정한 것과 이유:
- 바꾼 파일:
```
